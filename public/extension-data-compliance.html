Dreamlab Canvas Extension Data Compliance

Last updated: February 19, 2026

This page explains why Dreamlab Canvas requests each Chrome extension permission and how data use is constrained to the extension's single purpose: user-initiated content capture into Dreamlab.

Single Purpose

Dreamlab Canvas provides an always-on capture workflow across websites so users can save pages, images, selected text, screenshots, and recordings into Dreamlab collections.

Permission and Host Access Justification

  • contextMenus: supports user-triggered save actions from page/image/selection context menus.
  • storage: stores widget settings, excluded domains, and destination preferences.
  • activeTab: executes user-initiated capture actions on the active page.
  • tabs: tab query/orchestration and opening extension UI pages.
  • scripting: injects local extension scripts for picker and capture overlays.
  • <all_urls> host access: required for always-on cross-site widget behavior and capture entry points without repetitive prompts.

Remote Code Statement

The extension does not execute remote code. Runtime extension logic is packaged with the extension. The extension does not rely on eval, new Function, or externally hosted scripts to run extension features.

Data Use Commitments

  • No sale or transfer of user data to third parties except approved use cases necessary to provide the service.
  • No use of user data for purposes unrelated to the extension's single purpose.
  • No use of user data for creditworthiness or lending purposes.

Limited Use Statement

The use of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.
